# 车包存储与多服务器同步

RIAutomobility 以 `.riauto` 作为服务器权威的自定义车辆部件归档。服务器启动时加载这些
归档，并向客户端同步组件定义和所需资源。多个独立服务器实例也可以指向同一个权威目录，
同时保留各自的本地缓存。

## 默认目录

未配置共享目录时，服务器只扫描游戏目录顶层的 RIAuto 文件：

```text
<游戏目录>/riautomobility/*.riauto
```

只读取该目录顶层、扩展名为 `.riauto` 的普通文件；子目录、符号链接、`cache/` 和其他
文件不会被当作车包。无效归档会写入服务器日志并被忽略。

客户端缓存和临时文件始终位于自己的游戏目录：

```text
<游戏目录>/riautomobility/cache/
├─ packs/               # 从服务器取得的车包缓存
├─ server-transfers/    # 传输快照
└─ uploads/             # 编辑器“导出物品”的临时上传文件
```

缓存不是权威数据，不应复制到共享车包目录，也不应作为服务器迁移的来源。

## 配置共享目录

首次启动后编辑每个服务器实例的：

```text
config/riautomobility-common.toml
```

示例：

```toml
[carPacks]
sharedDirectory = "D:/MinecraftShared/RIAutomobility/packs"
scanIntervalSeconds = 3
```

| 配置 | 默认值 | 有效范围 | 说明 |
| --- | --- | --- | --- |
| `sharedDirectory` | `""` | 有效文件系统路径 | 空值使用 `<游戏目录>/riautomobility`；相对路径以游戏目录为基准 |
| `scanIntervalSeconds` | `3` | `1` 到 `300` | 运行中的服务器检查目录变化的间隔 |

同一组服务器必须把 `sharedDirectory` 解析到同一个目录。Windows TOML 路径建议使用
正斜杠；若使用反斜杠，需要按 TOML 字符串规则转义。

## 启动、热重载与客户端同步

服务器启动时会在独占目录锁内完成以下工作：

1. 扫描并验证全部顶层 `.riauto`；
2. 准备车架、车轮和引擎组件数据；
3. 准备供客户端使用的车包清单；
4. 同时安装组件数据和清单。

运行期间，后台监视器按 `scanIntervalSeconds` 检查文件名、大小、修改时间和修订标记。
检测到变化后，它先在后台准备新目录内容，再回到服务器线程应用并同步所有在线玩家。
若准备、应用或同步过程中失败，日志会报告错误，服务器会尽量恢复并继续使用上一份目录
内容，而不是保留一半更新的组件清单。

新玩家加入或数据包同步时，也会收到当前组件清单。组件定义会立即安装；模型资源缺失时
暂用占位模型。客户端在实际遇到某个组件时按需检查内容摘要，只下载服务器要求且本地
尚无匹配缓存的车包。

## 通过车辆导入台发布

管理员使用“导出物品”时，服务器会验证权限、归档大小、SHA-256、元数据、组件 ID、
BBModel 和贴图资源。验证通过后，发布过程使用：

- JVM 内锁与跨进程文件锁；
- 同目录暂存文件；
- 可用时的原子移动；
- 覆盖时的备份与回滚；
- 修订文件通知其他服务器实例。

发布完成的服务器立即重载；共享同一目录的其他进程会在自己的下一次扫描中检测变化。
普通玩家可以导出本地 `.riauto`，但不能通过编辑器发布到服务器权威目录。

## 手工维护建议

虽然服务器会验证目录中的归档，仍建议把手工文件操作安排在低负载时段：

1. 先把新文件复制到共享目录之外；
2. 完成复制后，再以同文件系统重命名到目标 `.riauto` 文件名；
3. 等待至少一个扫描间隔并检查每个服务器日志；
4. 确认在线客户端完成同步后再删除旧归档。

不要把尚未复制完整的文件直接写成 `.riauto` 目标名。监视器可能在写入途中检测到它；
此次重载会失败并保留旧目录状态，但会产生不必要的错误日志。

## 迁移已有服务器

1. 停止所有将要共享目录的服务器实例。
2. 创建新的共享目录。
3. 从原 `<游戏目录>/riautomobility/` 复制或移动顶层 `.riauto` 到共享目录。
4. 不要迁移 `cache/`、上传临时文件、预览归档或传输快照。
5. 检查是否存在同名车包，或不同归档声明同一个组件 ID。
6. 在每个实例中填写相同的 `sharedDirectory`。
7. 依次启动服务器并检查加载日志。

需要回退时，先停止全部实例，把各自的 `sharedDirectory` 清空，并把所需 `.riauto`
恢复到每个实例自己的 `<游戏目录>/riautomobility/` 顶层后再启动。

## 故障排查

### 服务器没有发现车包

- 确认文件位于配置目录顶层且扩展名为 `.riauto`；
- 确认它是普通文件而不是目录或符号链接；
- 检查 `sharedDirectory` 是相对于哪个游戏目录解析的；
- 查看日志中的 `Ignoring invalid RIAutomobility car pack`。

### 一台服务器更新，其他实例没有更新

- 确认所有实例解析到完全相同的共享目录；
- 确认 `scanIntervalSeconds` 没有被设置得过长；
- 检查各进程是否有读取目录和锁文件的权限；
- 等待一个完整扫描间隔后检查共享目录监视器日志。

### 客户端无法使用自定义组件

- 确认服务器日志没有报告清单准备或传输失败；
- 重新连接以触发完整清单同步；
- 不要手工修改客户端 `cache/packs` 来替代服务器发布；
- 若服务器已删除某车包，恢复对应归档或改用仍存在的组件。
