# 车辆钥匙与多座位

RIAutomobility 的机动车钥匙可以在车辆生成时建立一对一绑定，并限制驾驶、库存和部分
交互权限。自定义车架最多运行 8 个座位，0 号座位固定为驾驶位。

## 合成空白钥匙

```text
空      铁粒    铁粒
空      金粒    铁粒
空      铁粒    空
```

合成结果为一把空白机动车钥匙。

## 绑定车辆

1. 把空白钥匙放在副手。
2. 用主手放置已经组装好的机动车物品，或在机动车装配台上完成车辆组装。
3. 车辆成功生成后，副手钥匙自动绑定该车辆的 UUID，车辆进入钥匙保护状态。

没有在副手放置空白钥匙时，车辆仍可正常生成，但不会启用钥匙保护。现有空白钥匙不能
在车辆生成后补绑；需要在放置或组装的那一刻完成绑定。

## 谁拥有访问权限

满足以下任一条件即可访问受保护车辆：

- 玩家背包中有绑定该车辆的钥匙；
- 玩家处于创造模式；
- 玩家拥有命令权限等级 2；
- 车辆本身没有启用钥匙保护。

钥匙只需位于玩家背包任意栏位，不必拿在手中。访问权限会用于驾驶位、车辆 54 格库存、
命名牌重命名、撬棍/扳手拆解，以及声明 `requires_access` 的交互盒动作。

乘客位是否允许无钥匙进入由具体入口决定：默认的乘客上车与 `seat = -1` 交互盒动作
可以进入空闲乘客位；明确要求访问权限的动作会拒绝无钥匙玩家。0 号驾驶位始终检查钥匙。

## 定位车辆

手持已绑定钥匙右键时，服务器会显示车辆的整数坐标和维度：

- 若车辆位于当前维度，还会高亮车辆 200 tick（约 10 秒）；
- 若车辆在其他维度，只显示记录的维度与坐标；
- 定位使用后有 20 tick（约 1 秒）冷却；
- 若服务器已确认车辆被销毁，钥匙会自动恢复为空白；
- 若位置暂时不可用但车辆没有被确认销毁，钥匙保持绑定。

受保护车辆会定期更新位置记录。使用命名牌成功重命名车辆时，已加载的匹配钥匙也会更新
它们显示的车辆名称。

## 重置与恢复钥匙

把一把带绑定数据的机动车钥匙单独放入任意合成栏，即可得到空白钥匙。合成栏中不能有
其他物品。重置只清除钥匙自身的数据，不会解除车辆的保护状态；若没有其他匹配钥匙，
之后只能由创造模式玩家、管理员或恢复命令访问驾驶与受限功能。

权限等级 2 的玩家可以面向命令中的已保护车辆恢复一把新钥匙：

```mcfunction
/riautomobility key recover <vehicle>
```

命令会把钥匙放入执行者背包；背包已满时掉落到世界中。目标必须是仍处于钥匙保护状态的
RIAutomobility 车辆。

## 多座位操作

默认按键 `R` 的说明为“上车 / 切换座位”，可以在控制设置中重新绑定。

- 未乘车时：看向 RIAutomobility 车辆并按 `R`，进入第一个可用乘客位；
- 已在车上时：按 `R`，按座位索引循环到下一个空位；
- 循环到 0 号驾驶位时，没有匹配钥匙的玩家会跳过该座位；
- 无空位时保持当前座位。

自定义车架可以在车辆导入台中配置任意数量的座位数据，但当前实体网络状态最多跟踪前
8 个座位。座位索引按编辑器中的顺序从 0 开始。Molang 乘客视角查询和交互盒的
`mount.seat` 也使用同一套可视座位索引。

## 与交互盒配合

交互盒可以为车门或特定区域指定上车位置：

```json
{
  "type": "mount",
  "seat": 2,
  "requires_access": false
}
```

`seat = -1` 表示第一个可用乘客位；`seat = 0` 表示驾驶位。容器动作永远需要钥匙权限，
而 Molang 动作默认不需要权限。若同一次右键匹配的多个动作中有任何一条需要权限，
无钥匙玩家的整组动作都会被拒绝。完整规则见
[OBB 车辆交互盒](Vehicle-Interaction-Boxes.md)。
